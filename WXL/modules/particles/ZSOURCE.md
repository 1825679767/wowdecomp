# Native EXPT/EXP2 zSource ownership

This pending source stage converts a positive extended particle source point into the native M2 float track consumed by CParticleEmitter2. It adds no renderer/shader entry points and changes no emitter ordering, particle strides, material identities or draw grouping.

The extension is a source coordinate, not an opacity adjustment. Native plane/sphere/spline CreateParticle already calculate the initial direction from (0,0,zSource) toward the spawn point, then scale by the emitter speed and apply the native transform. Native emitter clones copy Params, including the scalar source point. The converted M2 allocation owns the immutable constant key until normal shared-model destruction; no raw pointer points back into a source chunk or temporary vector.

ApplyParticleExtensions keeps EXP2 precedence over EXPT. For a nonzero source point BakeZSource validates finite/nonnegative input and rejects values below the native SetZsource 0.001 epsilon. It admits only an empty/neutral constant pre-existing zSource track with no global loop, at most one sequence slot and one timestamp/key. Nonneutral, animated and globally controlled tracks remain refused because combining two source-point authorities is unproven. Negative source points remain refused because the modern primary record documentation only establishes positive source-point semantics.

The new key layout is native: one outer timestamp descriptor, one outer float-key descriptor, time zero, and one float key. All are appended at a four-byte aligned offset and bounded by the existing 64 MiB conversion limit. The track uses no interpolation and no global loop. Native M2Init requires sequence zero to exist and be inline (flag 0x20) before relocating those inner arrays against the model allocation; the stage refuses models without that proof. Other animation indices use the existing M2AnimateTrack<float,float> slot-zero fallback. Native initialization calls SetZsource with the first key, native animation/update retains its existing track handling, and native clones retain the initialized scalar.

For extra == 0 the original native track is preserved exactly. This retains existing models and avoids replacing an unrelated native animation with a neutral extension. Existing caller discard-on-refusal remains necessary: conversion may have appended earlier emitter keys before a later emitter fails. PrepareModel commits neither source storage nor the candidate allocation until every conversion/material/skin gate succeeds.

EXPT/EXP2 multiplier baking and all existing nonzero-cutoff restrictions remain. Layer/TXAC UV composition, refraction and geometry/child-model cutoff remain unsupported; this stage provides no such shader semantics. A source point may coexist with an otherwise admitted single-texture nonzero-cutoff emitter because source-point simulation and opacity sampling use independent native fields.

Primary semantics: https://skarndev.github.io/wowlib/python/m2/records/#wowlib.formats.m2.chunked.record.M2ExtendedParticleSimple documents positive zSource velocity from the source point to the spawn point; M2ExtendedParticle documents the same semantics for EXP2. Read October 16, 2026. Existing local donor normalization copies the target-shaped particle body and does not implement modern auxiliary zSource; the old x64 NeutralAux donor explicitly admits only zero. Therefore the native typed simulation is the implementation authority, not an old binary offset or the zero-only donor gate.
