# Native layered particles - pending source stage

The default-on Particles module now captures and renders a bounded three-texture donor family through native Gx. No injected offsets, x86 hooks, raw D3D device calls or global device replacement are introduced. DX11 and OpenGL implementations remain deferred. Models carrying unsupported multilayer contracts fail conversion; a supported recipe that loses runtime shader/texture readiness submits no first-texture fallback.

## Exact admitted subset

MD21 inner version274 with global flags0x3090, source MultiTexture flag, lit or unlit alpha/additive/Screen head-only, tail-only or combined head/tail sprites (source blend2/3/4/7), unsigned scale bytes, three file textures, empty geometry/child model names, neutral emitter TXAC, and no source Modx4/depth/refraction variant bits. The implementation does not interpret arbitrary auxiliary chunks. TXAC mesh rows are preserved and do not disqualify an otherwise neutral particle unless the independent EXPT converter's existing all-neutral rule applies. EXPT/EXP2 scalar and cutoff validation remains with ApplyParticleExtensions.

D3D9/9Ex must expose SM3 vertex/pixel targets, at least35 vertex constants and three texture units. Runtime also requires native shaders enabled, an exact source-to-emitter-to-active-Gx blend identity and a source-matching four-vertex/six-index or eight-vertex/twelve-index native particle shape. No OpenGL reinterpretation of D3D bytecode occurs. This subset is intentionally narrower than the old donor experiments: signed scales, SourceRGBModulationCandidate, TXAC1/1, BlendAdd, refraction and shadow/three-or-more-local-light variants are not asserted to be recovered.

## Capture and ownership

CaptureParticleLayers runs before M2Bytes::Convert and retains every admitted emitter's entire modern source record, original flags, packed texture indices, TXAC presence/row, both scale values and both scroll mid/range vectors. Three packed five-bit indices decode without losing the second and third texture. Captured source emitter count must match the normalized count. Sidecars live in native ModelAssets and are immutable shared_ptr recipes. Nonzero EXP2 cutoff accepts a layered emitter only when the exact admitted recipe record/flags still match its source bytes.

InitializeLoaded attaches both the immutable recipe and a binding with three HandleDuplicate texture references from that CM2Model instance texture table. Params copy construction carries both references into native emitter clones. ReplaceTexture refreshes all three references from the modified instance table after native replacements, so secondary/tertiary handles and clones do not retain shared-source or other-instance textures. A failed replacement binding keeps the required-recipe flag and suppresses that draw. Native handle close in the binding destructor releases each duplicate, including repeated texture identities; a clone can retain its binding after the original shared source dies. Allocation/readiness failure cannot clear the separate required recipe flag and thereby fall back to the normalized first texture.

## Vertex and shader implementation

Native BuildVertex remains authoritative for positions, atlas UV0, color/alpha, billboard, scale, spin, depth order and twinkle rejection. Immediately after each successful four-vertex native build, the adapter validates its four atlas corners and appends UV1/UV2 independently. Records stay in the native sorted order and each rendered native quad contributes four40-byte unlit or52-byte lit vertices, with one or two quads per logical particle. Any shape/UV failure invalidates the entire layer draw. Layered emitters are excluded from cross-emitter pooling in both the first-emitter dispatch and subsequent batch scan.

The extra-layer equations are ported from donor ParticleLayerPolicy Motion/ExpandQuad: sign-magnitude scroll divided by512; unsigned scale divided by32; independent deterministic starting offsets; velocity=mid+range*random; UV=start+velocity*particleAge+corner*scale. The native particle's stable randomSeed seeds this donor deterministic motion without advancing emitter RNG. This is a functioning donor composition policy; exact retail RNG sequence/parity is not claimed. Atlas UV0 remains the native mask UV rather than being forwarded into both extra channels.

The exact donor ParticlePrograms.hpp is retained with its generated SHA256 comments, together with original ParticleLayers.vs.hlsl and .ps.hlsl. The actual Unlit VS and TwoColorThreeAlpha/ThreeColorThreeAlpha PS compiled arrays are submitted through native CGxShader objects registered in the native device shader list, validated through its IShaderCreate/Valid path and destroyed through ShaderDestroy. No shader compiler or guessed FileDataID is required. The two-color kernel multiplies layer0/1 RGB and all three texture alphas; the three-color kernel multiplies all three RGBA samples. Color/alpha extension multipliers already baked into native keys are not applied twice.

Native custom PrimVertexFormat supplies Position(type4,offset0), Color0(type0,offset12), UV0/1/2(type3,offset16/24/32), all stride40; PrimVertexMask enables exactly those semantics. Native D3D9 IStateSyncVertexPtrs computes the stream stride as12+4+8+8+8=40, creates/caches the custom declaration from those semantics and retains existing buffer/index base-offset handling. No enum is repurposed and no built-in format is changed. Draws use the existing native quad index buffer and count/ranges bounded by16384 vertices.

## State and cutoff

Native ShaderEffect uses the same projection(c2..5), UV0(c6..7), fog(c30) and model rows(c31..) ABI as the retained donor Unlit program. UpdateProjMatrix, SetTexMtx_Identity and UpdateWorldViewMatrix populate its draw constants. Current c30 fog visibility and PS c2 fog RGB remain native SetupMaterial authority, including the native disabled-fog constant. PS c0=(1,1,max(nativeAlphaRef,lifetimeCutoff),0), so the captured native framebuffer blend remains and cutoff clips the composed alpha. Additive/Screen explicitly use black PS fog RGB while retaining native c30 visibility. Adjacent identical thresholds can share draws without reordering particles.

DrawScope retains native cached vertex attributes/mask/index, view, shader selections through RsPush/RsPop, PS c0/c2 and VS c2..7/c30..34. It restores through the same native ShaderConstantsSet and render-state APIs, forcing texture-unit cache updates and syncing restored programs before releasing draw-local registered shader refs. Pixel c2 and vertex c30 are reasserted from their saved native values after texture readiness; no replacement fog function is introduced. Each bound texture's original flags are captured before changes, temporary wrap/linear-point-mip sampling is restored per texture (including repeated identities), and native stages0..2 are forced through cache restoration. Temporary extended vertices use native streamed-buffer ownership.

The existing donor two-color/three-alpha and three-color/three-alpha kernels remain actual shader consumers. Their RGB output remains independent of opacity. Signed-scale status: the local donor explicitly excludes the high scale bit; the fetched primary record documentation establishes only a 2.5 fixed-point field, not its sign encoding or negative-zero interpretation. This stage therefore retains the signed-scale refusal rather than inferring two's complement or sign-magnitude from the different 16-bit scroll field. ## Native lit layer family

Source lighting flags are retained before normalization and continue to determine the native material. Shaded layer sprites now retain the complete native36-byte PNCT prefix and append independent UV1/UV2 at offsets36/44, producing52-byte vertices. Unlit sprites retain the existing24->40-byte route. Normal data is copied from native BuildVertex with finite/nonzero validation, not recomputed from a guessed emitter axis. The reserve/upload/size checks, custom Gx declaration and vertex mask all use the matching stride. Native Gx therefore creates the actual six-attribute Position/Normal/Color/UV0/UV1/UV2 declaration with a52-byte stream; its built-in format enum remains untouched.

The renderer consumes the exact precompiled donor Directional, DirectionalPoint and DirectionalTwoPoints VS arrays from the already retained ParticlePrograms.hpp, with the existing two layer PS kernels. Native s_lightEnabled must agree with the source/native material, local-light count must be0..2 and native shadow value must be zero. Each active local slot must have native ComputeLocalLights color.w==1, proving a real point-light slot; unsupported nonpoint local slots are refused because native code leaves their position data uninitialized. More local lights or shadow permutations are not approximated by discarding lights or reusing the nearest shader.

The native/donor constant ABI matches directly: c10 diffuse sun, c11 ambient sun, c12 sun direction, c17..20 point colors, c21..24 view-space point positions, c25 constant attenuation, c26 linear attenuation, c27 quadratic attenuation and c29 emissive/color bias. Native SetLocalLighting/ComputeLocalLights/SetupMaterial own those values. DrawScope snapshots c10..12/c17..27/c29 before texture readiness, reasserts the same bytes before lit dispatch and restores them through native ShaderConstantsSet and the existing typed backend synchronization. No light positions, colors, attenuation or bias are synthesized by this stage.

The selected VS multiplies the native particle color by native sunlight/point lighting and applies native color bias; the existing PS then consumes the same three textures and composed cutoff. Source blend2/3/4/7 and their native fog/equation contracts remain. Per-instance handle ownership, ReplaceTexture rebinding, clone lifetime, native sort/twinkle order and cutoff references are unchanged.

The three new VS names retain a native-device owner reference and participate in the existing DestroyParticleLayerPrograms cleanup before Gx device teardown. No per-draw shader recreation, process static device pointer, loader-lock cleanup, shader recompilation or direct raw-device binding is introduced.

Remaining concrete particle variants: shadow permutations; more than two local lights or nonpoint local slots; geometry/model/child particle paths; signed scale high-bit encoding; nonneutral TXAC; Modx4/unrecovered RGB modulation; unknown auxiliary chunks; source versions/global flags outside the admitted family; other blend modes; and non-D3D9 backends (DX11 belongs to the other chat). The existing deterministic extra-UV policy still does not claim retail RNG sequence parity. Source/API inspection is not compilation or visual acceptance; no build/tests/game execution occurred in this stage.
## Native tail and combined head/tail layers

Capture now accepts native HeadStyle0x20000 and TailStyle0x40000 independently, requiring at least one. Both original source bits remain in the immutable source recipe and complete source record. Runtime verifies those bits against the emitter's actual native head/tail flags, m_vertsPerParticle and m_indicesPerParticle before dispatch. Unsupported style mutation fails closed rather than reinterpreting an8-vertex particle as two independent logical particles.

Native SetParticleStyle defines head-only/tail-only as4 vertices and6 indices, and combined head/tail as8 vertices and12 indices. Native BuildVertex emits the head first, then tail, or only the requested shape. Tail positions remain native: backward velocity transformed into view space and multiplied by tailLength, optional clamp to particle age, velocity-facing perpendicular width and the native near-zero-projected-velocity quad fallback. This stage never reconstructs those positions or changes source tailLength/UV/spin/velocity semantics.

After the complete native BuildVertex call, the adapter verifies the expected4/8 appended vertices and processes each consecutive native quad through the same retained donor layer equations. Each quad keeps its own native UV0 atlas cell (headCellTrack or tailCellTrack) and its full24/36-byte position/normal/color prefix. Its UV1/UV2 are independently generated from that quad's verified corners with the same source particle age and stable native particle seed. Combined shapes therefore retain native ordering and a coherent source layer motion without borrowing the first quad's mask UVs or collapsing the tail to a sprite.

Reserve size and rendered-buffer validation now use native vertices-per-particle with the unchanged40/52-byte extended stride. Native rendering still caps the complete draw at16384 vertices, giving4096 one-quad or2048 two-quad logical particles. The existing shared native quad index buffer already covers this maximum, so no new index format, topology, shader or backend path is introduced.

Cutoff remains one sample per successfully rendered logical particle. Both quads of an8-vertex particle share that same source lifetime sample. Adjacent identical threshold groups use start=begin*indicesPerParticle, count=(end-begin)*indicesPerParticle, minIndex=begin*vertsPerParticle and maxIndex=end*vertsPerParticle-1. Native Gx retains its own stream/index base offsets. Sorting and twinkle rejection continue to happen only in the native particle builder; no quads or cutoff samples are independently resorted, omitted or duplicated by the layer adapter.

Existing lit/unlit donor VS programs, three-texture PS kernels, alpha/additive/Screen contracts, state restoration, persistent shader ownership, per-instance texture replacement and clone lifetimes are unchanged. Signed-scale and nonneutral-TXAC gates remain. No build/tests/game execution occurred. Runtime acceptance still needs representative tail-only and combined effects across velocity/clamp/fallback, independent head/tail atlas tracks, sorted/twinkle paths and nonzero cutoff, plus visual/performance observation for the exact combined output.
