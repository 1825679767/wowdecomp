# Prepared WMO native reference bounds

Modern WMO groups use validated complete geometry and then the stock native parser. The68-byte MOGP header also controls unchecked native batch/portal/reference traversal; validating MOBA rows alone did not bound these counters. Native FixColorVertexAlpha runs inside group.Create, before the adapter's post-create checks, so late clamps could not protect it.

Before publication Group now bounds transparency/interior/exterior counts individually and their widened sum against actual MOBA length (subset totals remain allowed). Active portal start/count ranges must fit the actual root MOPR table. Nonzero authored environment-table indices must fit the actual MFOG table. Entry0 must exist for a root with groups because native interior lookup reads that entry unconditionally; no replacement entry or fog behavior is synthesized.

Root portal records must reference real MOPV vertices. MOPR references must name a real MOPT portal and MOGI group; actively referenced portals require at least three vertices for native polygon consumers. Unused zero-count portal ranges are retained. All checks happen on source-owned serialized bytes before root/group allocation publication; classic native files and the native renderer/culling/fog implementations remain unchanged.

These are source-confirmed malformed-family boundaries, not a claim a mounted asset triggered them. No new bad-data probe suite, game/account action or archive mutation. Broad world/visual acceptance remains pending.
