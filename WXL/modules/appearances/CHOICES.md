# Native retail choices and skinned models

RetailChoices.cpp is the single native five-axis authority. It checks mounted recipe/layout tables and exact default/native model identity, including an MD21 source, before routing classic byte axes through ordered retail choices. Classic actors retain classic CharSections behavior. Counts/normalization/set/next/previous/random/nth and native Init agree, with at most256 values on each byte axis. Extra options use explicit uint32 choice IDs via Lua APIs and a per-component revision; the atlas signature includes that revision. Models, schemas and cached authority require restart after data changes.

Explicit extra choices are owned by the component and preserved only across same race/sex/model-family rebuilds. Default extras need no override. Nondefault extras use the appearance-session hello/prepare owner and require an exact server prepared ACK before one native creation dispatch; they are never silently truncated or discarded. Selection and active-player snapshots restore validated option IDs transactionally. Alternate/synthetic profiles remain refused. Standard five-byte character creation remains the existing native wire path. Server persistence and custom UI button generation are not proven by these APIs.

Recipe skinned children are owned by AppearanceAssets and retain their pose source through CM2Model::SetSkinningSource. Child render textures use the completed component-owned sheets. The native worker evaluates child material tracks after parent pose completion, copies verified same-index matrices and transforms, and excludes children from independent worker scheduling. Main-thread traversal includes lighting/shadows and scene changes. Detachment retires children before owned sheets/root model. Bind topology/CRC/flags/pivots/count must match; no pointer-offset hooks or guessed bone remaps. Appendage bounds and subset skeleton support remain work.
