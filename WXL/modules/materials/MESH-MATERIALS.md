It does not widen the vendor converter's generic named-effect admission table. The model-owned loading seam returns a private sanitized SKIN clone only after a complete bounded source contract succeeds; exact original companion bytes remain available for native PrepareSkin comparison and provenance.

Admission requires D3D9/9Ex Shader Model 3, enabled native Materials, MD21 with MD20 version274, one inline bone, one named skin profile, one skin section, one batch, one section bone/influence, source0x8015/two textures, no secondary material layer, exactly two file textures with nonzero TXID identities and no overriding filename, source material blend7 with native-supported flags, and two complete weight/transform lookup entries. Unknown source IDs, three-stage sources, missing/ambiguous mappings, unsupported backends, and insufficient capabilities retain the existing refusal/fallback behavior. The existing material blend7 implementation remains the framebuffer authority; no particle Screen semantics are introduced.

`MeshMaterials::Source` owns immutable exact source batch bytes, model/SKIN fingerprints, both texture indices/TXID values, both weight/transform references, source material flags and blend. The native output batch must match the source indices and the exact conversion layout. ## Program and state lifetime

The shader kernel is copied byte-for-byte from the donor generated headers. The VS uses native c31-c33 actual bone0 model-view rows, c2-c5 projection, c6-c9 two UV transforms, c10-c12 lighting, c28-c29 colors and c30 fog. Native DrawBatch uploads the selected bone matrices immediately before this draw seam. Source admission also proves each referenced vertex has weights255/0/0/0, boneindices0, skin palette properties0 and a sole palette mapping to bone0; the live palette mapping is checked again. This avoids assuming that arbitrary weighted geometry can use a nonweighted VS. The PS uses donor base+overlay/fog equations and base-alpha times grazing-angle cubed. These are donor equations, not a generic retail shader implementation.

Two uniquely named real CGxShader objects live in the native device shader lists with one owned reference. Their compiled bytes/target must match exactly on reuse; Valid uses native IShaderCreate and the existing backend reset invalidation/recreation. No static device pointer is retained and programs are not created or destroyed per draw. Explicit DestroyPrograms runs in GxDevDestroy before backend destruction and releases these references through native ShaderDestroy. Native RsPush/RsPop covers both shader selections, followed by the correctly typed D3D9 or D3D9Ex IStateSync, keeping native cached and live bindings aligned for subsequent draws. No shader constants, texture/sampler settings, blend factors, vertex declarations, particle streams, model coordinates or camera state are overwritten. Creation/validation failures return to the native draw. Merge this teardown call alongside the independent particle program cleanup.
